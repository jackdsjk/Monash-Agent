# Cove MVP 范围与优先级决策

> 日期：2026-10-29
>
> 状态：初版决策，待项目所有者确认
>
> 关联：[PRD](PRD-Monash-Agent.md) · [路线图](project-resume-roadmap.md) · [评测结果](evaluation-harness.md) · [模型回放](model-eval-gpt-5.6-luna-2026-10-29.md) · [匿名 Demo](../demo/README.md)

## 1. 决策摘要

第一版只做一件事：

> **让一个普通 Monash 学生用最少操作确认“上次查看之后，我有没有错过真正重要的事”，并在需要时回到原文。**

P0 锁定为五个能力域：

1. 本地 Web 入口与首次连接（桌面壳 P1）；
2. Gmail、Ed、Moodle 的只读同步与同步状态；
3. Since Last Check 简报与注意力分组（含精确去重）；
4. 关键结论的原文证据与来源跳转；
5. 用户纠错与本地数据控制。

这不是“把 Demo 打包”，也不是“再做一个日历”。第一版不包含语义去重、教师结论自动提炼、OnTrack、提醒、问答或 MCP 入口。

## 2. 目标用户与核心任务

**用户：** 同时使用 Moodle、学校邮箱和 Ed，需要定期确认课程动态，但不想逐条阅读所有通知与讨论的 Monash 学生。

**核心任务：** 用尽可能低的注意力成本确认自己没有漏掉重要要求、截止变化或教师答复。

**第一版成功标准：**

- 通过本地启动器打开 Web App，完成连接三个来源和第一次同步；桌面安装包不作为本轮门槛；
- 用户能在一次简报中看到“必须处理 / 重要更新 / 教师答复 / 新资料 / 已折叠”；
- 每条重要结论都能看到原文证据、来源和作者身份；
- 用户可以纠正错误判断，纠错在重启后仍然存在；
- 同步失败、无新内容和来源不可用都有明确状态，不静默失败。

以下仍不是第一版承诺：节省了多少分钟、提升留存、避免了多少次遗漏、付费意愿。

## 3. 方法与限制

使用 ICE 作为初筛：

- **Impact（1–5）**：对“低精力确认没有漏掉重要信息”的贡献；
- **Confidence（1–5）**：有多少来自 Gold Set、模型回放或 Demo 的证据；
- **Ease（1–5）**：5 表示实现和验证最容易；
- **ICE = Impact × Confidence × Ease**，满分 125。

评分只用于功能排序，不用于推翻基础依赖。本地 Web 入口、只读同步和本地数据控制属于“没有它就没有产品”的基础项，即使 Ease 低也不能被砍掉。

限制：

- 55 条样本是匿名改写 prototype，不是最终真人 Gold Set；
- 模型只做了一次单模型回放，没有 holdout、第二模型或真人复核；
- 尚无外部用户研究，用户的授权意愿、留存和实际节省时间仍是假设；
- 本项目是独立产品，MVP 必须控制实现面，不能先做完整平台；
- 未计算 Opportunity Score：当前没有用户满意度数据，先使用 ICE 做初筛。

评分说明：

- “原文证据”分数最高，因为它是信任前提，也是 PRD 已经明确的硬边界；
- “同步状态”比“同步本身”更容易做，却直接决定用户是否敢相信简报；
- 匿名演示模式分数不低，但它是验证和展示资产，不是第一版用户价值，因此放在 P1；
- 课程归属的证据不足：第一轮 39 封邮件中有 24 封未归属课程，先允许显示“未归属”，不把不准确的自动归属当成 P0 承诺。

P0 的推荐交付顺序是 A → B → C → D → E，而不是按 ICE 分数机械排序：证据分数最高，但没有同步和简报就没有内容可展示；本地 Web 入口和同步的 Ease 低，却是不可跳过的前置条件。

## 5. P0 范围与验收标准

### A. 本地 Web 入口与首次连接

包含：本地 Web App（运行在 `127.0.0.1`）；启动器/启动命令；首次连接引导；三个来源的连接/断开状态；失败原因说明。

验收：

- 通过一个启动器或一条文档化命令打开本地 Web App；桌面安装包不在本轮验收范围；
- 首次启动能完成 Gmail、Ed、Moodle 的连接或明确失败原因；
- 连接失败时用户可以重试，不出现无反馈的空白页；
- 所有来源只读，不提供代发消息、提交作业或修改源数据的能力。

### B. 三源只读同步与同步状态

包含：Gmail、Ed、Moodle 的最小纵向切片；手动同步；最近成功时间；失败状态；同步范围说明。

验收：

- 三个来源至少各完成一次成功同步；
- 每条来源显示最近成功时间、当前状态和失败原因；
- 同步失败时不覆盖已有数据，也不把旧数据标成新数据；
- 同步条目保留稳定 ID，重复运行不产生重复条目。

### C. Since Last Check 简报与注意力分组

包含：自上次查看窗口；“必须处理 / 重要更新 / 教师答复 / 新资料 / 已折叠”分组；精确重复合并；空状态；标记本次已查看。

验收：

- 首次打开显示最近 24 小时内容，之后以用户上次查看时间为准；
- 重要信息优先展示，低价值内容默认折叠；
- 同一来源的精确重复只展示一次；跨来源重复保留全部来源；
- 没有新内容时显示明确空状态，不展示旧内容冒充新内容；
- “标记本次已查看”后窗口正确推进。

### D. 证据、来源与原文跳转

包含：关键原句；作者角色；来源；时间；原文链接；不确定提示。

验收：

- 每个 `critical` / `important` 结论都有原文证据句；
- 证据句必须是原文的连续子串，不能是模型改写；
- 用户可以从卡片打开来源详情或原文；
- 不确定或缺少权威答复的内容明确标注，不写成确定结论；
- 高风险结论不能只给摘要，必须能回到证据。

### E. 用户纠错与本地数据控制

包含：标为重要/不重要；分类反馈；纠错持久化；查看和清除本地数据。

验收：

- 用户可以在卡片或详情中标记重要/不重要；
- 用户可以反馈内容类型、重要性或行动要求错误；
- 纠错在应用重启后仍然存在；
- 用户可以清除全部本地数据，并看到清除结果；
- 产品不自动执行任何外部写操作，不把纠错发送给第三方。

## 6. P1：第一版之后

| 功能 | 为什么后置 |
|---|---|
| 课程自动归属 | 当前证据不足；先以“未归属”降级，避免把猜测写成课程事实 |
| 教师结论提炼 | 第一版先展示教师答复原文；自动提炼需要更严格的忠实度评测 |
| 语义去重 | 精确去重已能处理一部分噪音；跨源语义合并需要 pairwise 评测 |
| 同步自动重试 | 第一版先暴露失败并允许手动重试；后台重试属于可靠性增强 |
| 匿名演示模式 | 已存在，保留用于展示和安全测试；不阻塞真实产品闭环 |
| 桌面壳与安装包 | 本地 Web App 验证 P0 后再评估 Electron；不作为第一版门槛 |

## 7. 明确不做

- 以聊天框为主体的通用 Agent；
- 自动提交作业、回复教师或代表用户发消息；
- 单纯的日历、截止日期提醒器；
- OnTrack 和更多学校来源；
- 个性化排序、规则解释、复杂后果分析；
- 增长、付费、内容运营；
- 为匹配 JD 增加无关的 Dify、Coze 或多 Agent 功能；
- 继续打磨 Demo HTML（后续专门阶段处理）。

## 8. 唯一核心流程

```text
首次启动
→ 连接 Gmail / Ed / Moodle
→ 首次同步
→ 自上次查看简报
→ 查看关键结论与证据
→ 必要时打开原文
→ 标记重要/不重要或反馈分类
→ 下次巡检
```

异常路径必须可见：

- 来源未连接：告诉用户哪个来源不可用，不假装完整；
- 同步失败：保留旧数据，显示失败原因和重试入口；
- 无新内容：明确空状态；
- 不确定内容：标记待确认，不写成正式要求；
- 高风险结论：必须能打开原文。

## 9. 证据与假设

### 已有证据

- 7 天内 39 封邮件和 68 个 Ed 主题，说明信息量和跨源混杂真实存在；
- 39 封邮件中 24 封未被现有规则归属课程，说明课程归属仍是难点；
- 规则 baseline：重要信息召回率 89.7%、关键误报率 0.0%；
- 模型回放：召回率 100.0%、精确率 90.6%、关键误报率 22.2%；
- 模型与规则在 55 条中各有 10 条“只有自己全对”，说明混合架构有依据；
- Demo 已验证简报、筛选、详情、证据高亮、纠错和空状态都能操作。

### 仍是假设

- 目标用户愿意同时授权 Gmail、Ed 和 Moodle；
- 本地优先、无云端账号的产品形态可接受；
- 五段式简报比按时间或按课程浏览更有效；
- 用户愿意花时间纠错，且纠错能改善后续判断；
- 本地启动器不会成为首次使用的门槛；
- 第一阶段的信息量足以形成日常使用习惯。

### 尚未验证

- 实际节省的阅读时间；
- 留存、付费意愿和推荐意愿；
- 重要性的跨课程一致性；
- 真实账号下的 SSO、MFA、会话过期和同步可靠性；
- 摘要忠实度和语义去重的真实错误率。

## 10. 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| SSO / MFA / 会话过期 | 首次使用失败，无法验证价值 | 复用已验证的适配层；连接状态和失败原因必须可见 |
| 模型误报 `critical` | 用户不再信任简报 | 代码护栏 + 证据约束 + 用户纠错，不让模型独立决定高风险 |
| 课程归属不足 | 简报难按课程阅读 | 先显示“未归属”，P1 再提高归属率 |
| 隐私与本地数据 | 用户不敢授权 | 只读、本地存储、可查看和清除、无第三方回传 |
| 范围膨胀 | 第一版无法交付 | 以本文 P0 为准，新增需求进入 P1/P2 并记录理由 |
| 只有 prototype 样本 | 指标不能代表真实效果 | 真实用户测试前不对外宣称时间节省或留存 |

## 11. 对现有文档的影响

- PRD 第一版范围以本文 P0 为准；
- 路线图第三步从“待补”更新为“P0 初版已锁定”；
- 评测和模型回放保留为回归基线，不因 MVP 取舍而删除；
- Demo 保留为匿名原型，不纳入 P0 交付验收；
- 桌面壳与安装包移到 P1，本地 Web App 是当前验证形态。
