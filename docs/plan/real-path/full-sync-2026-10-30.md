# 全量同步设计（2026-10-30）

## 目标

新用户第一次连接来源后，执行一次**无边界全量**；完成后的日常同步只做增量。

全量不是单个 HTTP 请求，而是本地后台任务。

## 当前边界

- Gmail：`listAllMessageIds` 以 `maxResults=100` 分页，带 `includeSpamTrash=true`；逐封读取并入库；
- Ed：所有课程（含 archived），每门课 `limit=100` 分页拉全部 thread；
- Moodle：所有 enrolled courses，逐课程抓取所有 section/activity，替换该课程本地缓存；同时同步 assessment 和 forum。
- 全部完成后写 `full_sync_completed_at`；任一来来源失败则不标记完成。

## 进度与恢复

- `POST /api/sync/full` 启动后台任务，立即返回 `202`；
- `GET /api/sync/status` 返回每个来源的 `processed/total/status`；
- UI 在数据源页显示逐来源进度；
- 日常 `/api/sync` 只做增量：Gmail history、Ed 最新页、Moodle assessment/forum；
- App 打开时最多每 5 分钟触发一次增量（sessionStorage 限流）。

## 已知限制

- Gmail 全量按 100 ms/封节流，避免触发 6,000 quota units/min 的 per-user 限流；678 封约 1–2 分钟，数万封会很久；
- 全量任务进程重启后不会从断点恢复，直接重新跑（upsert 不会产生重复条目）；
- Ed 全量目前拉 thread 列表，不额外展开所有 reply 正文；
- Moodle 全量只抓课程页可见的 section/activity，不下载资源文件本身；资料文件按选择下载；
- Moodle 资料缓存按课程替换，不会删除未出现在课程页的旧文件。

## 验证

- `POST /api/sync/full` 返回 job；
- `GET /api/sync/status` 进度更新；
- Gmail 全量 678 封、Ed 1586 threads、Moodle 10 courses/535 items（当前账号实测）；
- UI 全量按钮/进度条、增量打开同步；
- `npm test`、`npm run check`、Playwright E2E。
