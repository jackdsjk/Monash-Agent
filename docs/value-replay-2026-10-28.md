# 信息分诊价值回放：第一轮记录

> 日期：2026-10-28
>
> 状态：初步回放；55 条匿名改写样本已完成双轮独立标注和项目所有者复核，可用于原型评测；真实样本替换仍待完成

## 1. 回放问题

这次回放验证的不是“能否读取学校平台”，而是：学生是否面对足够多、足够混杂的信息，以至于需要一个产品替他完成第一轮巡检、阅读和筛选。

## 2. 数据口径

数据来自现有远端 D1 的只读查询，没有修改任何记录，也没有把完整私人正文写入仓库。

- Gmail 和 Ed 的 7 天统计按内容发布时间计算；
- Moodle assessment 的 `timestamp` 是截止时间，不能作为发布时间使用；
- 当前数据来自单个项目所有者账号，只能证明问题存在，不能代表全部学生；
- 当前同步窗口和连接器覆盖可能造成样本偏差。

## 3. 初步事实

| 观察 | 结果 |
|---|---:|
| 最近 7 天 Gmail 邮件 | 39 |
| 最近 7 天 Ed 主题 | 68 |
| 两类内容合计 | 107 |
| Ed 教学人员发起主题 | 7 |
| Ed 学生发起主题 | 61 |
| Gmail 已归属课程 | 15 |
| Gmail 未归属课程 | 24 |
| 当前活跃 Moodle assessment | 6 |

抽样中已经观察到：

1. 教学团队将同一提醒同时发到 Ed 和邮箱，但两个标题并不完全一致；精确标题去重无法识别。
2. Ed 中大量内容是学生问题、学习记录和作业细节讨论；只按“有新帖”通知会制造更多噪音。
3. 少量教师发布或教师答复可能对全班具有价值，不能把所有学生主题一律略过。
4. 多数近期邮件尚未归属课程，说明课程识别与相关性判断仍是核心产品问题。
5. Moodle、Ed 和邮件的时间字段语义不一致，统一时间线必须区分“发布、发现、截止、更新”。

## 4. 当前判断

**继续验证，不直接进入完整 UI 开发。**

第一轮数据支持“信息量和分诊成本真实存在”，但还没有证明：

- 107 条内容中究竟有多少真正值得用户看到；
- Agent 能否在不漏掉重要内容的前提下显著压缩信息；
- 简报是否比用户直接查看平台更快、更可信；
- 用户是否愿意持续授权并使用该产品。

## 5. 继续 / 停止标准

完成首批不少于 50 条人工标注后，满足以下条件才进入 MVP 主体开发：

1. 样本中同时存在 `critical/important` 与大量 `reference/skip` 内容，证明“分诊”而非单纯聚合有意义；
2. 至少发现若干只有阅读正文、教师回复或跨源合并后才能判断的案例；
3. 人工标准能够稳定解释为什么展示或折叠，第二轮复标没有大面积推翻；
4. 基线方案能高召回重要信息，并为关键结论提供原文证据。

出现以下情况则收缩或停止当前方向：

- 绝大多数内容仅凭平台现有排序就能可靠处理；
- “重要”高度主观，无法形成可解释的共性规则；
- 为避免漏报必须把几乎所有内容都展示，无法真正减少阅读成本；
- 数据授权、稳定同步或隐私成本高于用户获得的价值。
