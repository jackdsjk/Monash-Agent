## 1. 先说参考对象

Ant Design 仓库里没有“Web 设计 skill”。`.agents/skills/` 下是 changelog、commit、PR、issue、test、release 的维护技能，和产品界面设计无关。

真正可用于设计的是：

- `DESIGN.md`：Ant Design v6 的 token、排版、布局、组件和交互规范；
- `docs/spec/values.zh-CN.md`：自然、确定、意义感、生长性；
- `docs/spec/layout.zh-CN.md`：画板、栅格、8px 模度、左右布局；
- `docs/spec/detail-page.zh-CN.md`：详情页“直截了当、层次分明、化繁为简”；
- `docs/spec/feedback.zh-CN.md`：提示、过程反馈、结果反馈；
- `docs/spec/data-display.zh-CN.md`：卡片、折叠、表格的使用边界。

本文把 Ant Design 当作**设计系统参考**，不是照搬它的后台控制台外观。Ant Design 服务的是高密度企业系统；Cove 是面向学生的个人阅读产品，应该借用它的秩序、状态和组件语义，而不是它的蓝色、密集表格和后台气质。

## 2. 设计定位

**一句话：** 一份安静、可核对的校园信息简报。

三个关键词：

- **Calm**：页面不制造新的焦虑；重要内容靠层级和证据，而不是满屏红色；
- **Certain**：用户始终知道数据是否同步、内容从哪来、判断依据是什么；
- **Evidence-first**：任何高风险结论都能回到原文，不把模型推断写成学校事实。

不在第一版追求“炫技的 AI 感”。模型是辅助判断层，界面首先是一份可扫读、可追踪的简报。

## 3. 从 Ant Design 借什么，不借什么

| 借用 | 不借用 |
|---|---|
| 4/8px 网格、克制的圆角和阴影 | 默认 Ant 蓝作为主色 |
| 固定侧栏 + 主内容区的左右布局 | 中后台式密集表格作为主界面 |
| Card / Drawer / Alert / Badge / Tag 的语义 | 一排四个同等权重的数据卡片 |
| 明确的 hover / focus / loading / empty / error | 用颜色堆叠表达重要性 |
| 14px 正文、400/600 两个字重 | 9–10px 的装饰性小字 |
| 一个页面一个主按钮 | 多个 primary 按钮并列 |
| 4px 间距 token、6/8px 圆角 | 胶囊按钮、卡片悬浮跳动 |

## 4. 视觉系统

### 4.1 色彩

Cove 用深绿作为 primary，而不是 Ant Design 默认的 `#1677FF`。原因是：

- 绿色更接近“校园、安静、整理”的产品气质；
- 白字在 `#1677FF` 上的对比度不足，Ant Design 自己的 DESIGN.md 也提示了这一点；
- `#1F5A46` 上的白字对比度约 8.05:1，满足正文和按钮文字要求。

| Token | 值 | 用途 |
|---|---|---|
| `colorPrimary` | `#1F5A46` | 主按钮、链接、选中态 |
| `colorPrimaryHover` | `#2B6B54` | hover |
| `colorBgLayout` | `#F5F5F5` | 页面底色 |
| `colorBgContainer` | `#FFFFFF` | 卡片、面板、抽屉 |
| `colorText` | `rgba(0,0,0,0.88)` | 正文 |
| `colorTextSecondary` | `rgba(0,0,0,0.65)` | 说明文字 |
| `colorTextTertiary` | `rgba(0,0,0,0.45)` | 元信息 |
| `colorBorder` | `#D9D9D9` | 控件边框 |
| `colorBorderSecondary` | `#F0F0F0` | 分隔线 |
| `colorError` | `#CF1322` | 必须处理、错误 |
| `colorWarning` | `#D48806` | 重要、待确认 |
| `colorSuccess` | `#389E0D` | 同步成功、已保存 |
| `colorInfo` | `#0958D9` | 教师答复、说明信息 |

注意力状态不只靠颜色表达，必须同时有图标或文字：

| 注意力层级 | 表达 |
|---|---|
| 必须处理 | `Badge status="error"` + “必须处理” |
| 重要更新 | `Badge status="warning"` + “重要” |
| 教师答复 | `Badge status="processing"` + “教师答复” |
| 新资料 | 中性 `Tag` + “学习资料” |
| 已折叠 | 中性文字 + 折叠区 |

关键约束：**不要用 9px 彩色文字承载 critical**。Ant Design 的 tag 不适合作为 critical 状态；critical 用状态徽标、左侧 2px 强调线和正文说明，颜色只做辅助。

### 4.2 排版

Ant Design 的基础是 14px，而不是 16px。Cove 的阅读密度介于“个人阅读”和“信息列表”之间，沿用 14px 正文：

| 层级 | 规格 | 用途 |
|---|---|---|
| Page title | 30/38, 600 | “自上次查看” |
| Section title | 20/28, 600 | 必须处理、教师答复 |
| Card title | 16/24, 600 | 单条信息标题 |
| Body | 14/22, 400 | 原文、说明 |
| Meta | 12/20, 400 | 来源、课程、时间 |
| Tag | 12/20, 400 | 类型、行动 |

只使用 400 和 600 两个字重；不用斜体作为界面强调。数字使用 tabular numerals，保证统计和时间的列对齐。

字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", "PingFang SC", "Microsoft YaHei", sans-serif`。

### 4.3 间距、圆角和阴影

- 基础单位：4px；常用节奏 4 / 8 / 16 / 24 / 32；
- 控件高度：32px；输入框、按钮、Select 对齐；
- 圆角：控件 6px，卡片/抽屉 8px，Tag 4px；
- 卡片间距：16px；区块间距：32px；页面左右 padding：32px（移动端 16px）；
- 默认扁平：用边框和底色分层；阴影只用于 Drawer、Modal 和浮层；
- hover 不做上下位移；用边框色、底色或文字色变化。

### 4.4 动效

- 状态变化：0.1s；
- 展开、淡入：0.2s；
- Drawer / Modal：0.3s；
- 只使用 Ant Design 的 motion token 或等价的 ease-in-out；
- 尊重 `prefers-reduced-motion`。

## 5. 布局与导航

### 5.1 画板与栅格

- 设计画板：1440 × 900；
- 侧栏：232px 固定；
- 主内容：最大 960px，左右留白 32–48px；
- 内容区可用 12 栅格，feed 卡片单列，不做 2×2 卡片网格；
- 阅读宽度控制在约 70–80 个西文字符，避免长行。

### 5.2 页面骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ Sider 232                    │ Main                           │
│                              │                                │
│ cove.                        │ 自上次查看         [同步] [已查看]│
│                              │ 24 小时内 14 条更新，6 条需处理  │
│ ▸ 简报                       │                                │
│   数据源                     │ [14] [6] [1] [15]              │
│   设置                       │                                │
│                              │ [全部|Gmail|Ed|Moodle] [搜索] [只看行动]│
│ 来源状态                     │                                │
│ Gmail 25                     │ 必须处理 6                     │
│ Ed 25                        │ ┌──────────────────────────┐   │
│ Moodle 5                     │ │ 卡片                     │   │
│                              │ └──────────────────────────┘   │
│ 本地数据说明                 │ 教师答复 1                     │
│                              │ ...                            │
└──────────────────────────────┴────────────────────────────────┘
```

### 5.3 响应式

| 宽度 | 行为 |
|---|---|
| ≥1200 | 232px 侧栏 + 960px 内容 |
| 768–1199 | 侧栏折叠为 72px 图标栏，内容自适应 |
| <768 | 收为 72px 图标栏；内容单列；Drawer 全宽（顶部导航抽屉留到后续版本） |

第一版优先桌面浏览器；移动端只保证可用，不追求完整编辑体验。

## 6. 信息架构

### 6.1 导航

| 入口 | 内容 |
|---|---|
| 简报 | 自上次查看 / 全部内容 |
| 数据源 | 三个来源的连接状态、最近同步、范围说明、重新授权 |
| 设置 | 本地数据、清除数据、诊断信息、关于 |

第一版不做首页 Dashboard、不做多标签工作台、不做聊天主入口。

### 6.2 首次使用

使用 Ant Design `Steps`，三步：

1. 连接来源：Gmail、Ed、Moodle；每张来源卡显示状态、权限范围和“连接”按钮；
2. 首次同步：显示进度、失败原因、重试；
3. 查看第一份简报：进入“自上次查看”，用空状态解释下一次会发生什么。

### 6.3 简报页

从上到下：

1. **页面头**：日期、标题、一句副标题；右侧一个主按钮“标记本次已查看”，一个默认按钮“立即同步”；
2. **统计条**：`Statistic` 四项：本次视图、必须处理、待确认、已折叠；每项不超过 96px 高；
3. **筛选条**：来源 `Segmented`、搜索 `Input`、只看行动 `Switch`；筛选条紧贴列表，不悬浮；
4. **正文**：按注意力层级分段，每段标题带数量；卡片单列；
5. **页脚**：演示数据说明、快捷键提示、隐私边界。

不要把所有统计做成四个大卡片；统计条是辅助，不是页面主体。

### 6.4 卡片

卡片只承担四件事：

- 这条信息是什么（标题）；
- 为什么值得看（原文证据句）；
- 它属于哪里（来源、课程、时间、类型）；
- 我能做什么（查看原文、标为重要、标为不重要）。

结构：

```text
[来源] [课程] [时间]                    [状态徽标]
标题
“原文证据句”
[内容类型] [行动要求] [打开建议]
查看原文 · 标为重要 · 不重要
```

规范：

- 卡片 padding 24px；标题与证据间距 8px；
- 证据句最多两行，超出截断；完整原文只在 Drawer；
- 元信息 12px，不用纯色小字表达状态；
- critical 卡片左侧 2px `colorError` 强调；其他层级不加彩色边框；
- 已读卡片降低文字对比，但不降低到不可读；
- 置顶/反馈只加一个 Tag，不改变卡片结构。

### 6.5 已折叠区

使用 `Collapse`，默认收起；标题显示数量；展开后仍是卡片列表。折叠不等于删除：用户仍可搜索、恢复、查看原文。

### 6.6 详情 Drawer

从右侧打开 640px Drawer（窄屏全宽），保留简报上下文。不使用居中大 Modal 作为主详情，因为用户需要边看列表边核对原文。

结构：

1. 头部：来源、课程、时间、关闭；
2. 判断摘要：状态、内容类型、行动要求、打开建议；
3. 原文：完整文本，证据句用 `mark` 高亮；
4. 模型说明：模型名称、预录/实时状态、判断理由（如果未来支持）；
5. 用户反馈：标为重要/不重要、分类反馈、补充说明；
6. 底部：打开原始来源、关闭。

详情页遵循 Ant Design 的“直截了当、层次分明、化繁为简”：平铺信息、用不通栏分隔线分组、不要多层折叠。

### 6.7 反馈 Modal

反馈用 Modal + Form：

- 原因：内容类型 / 重要性 / 行动要求 / 其他（Radio）；
- 说明：可选 TextArea；
- 保存：主按钮；取消：默认按钮；
- 保存后 `message.success`，Drawer 内显示“已反馈”；
- 只写本地，不发外部服务；不承诺“AI 会立刻学会”。

## 7. 状态设计

| 状态 | 表现 |
|---|---|
| 首次加载 | 卡片骨架屏（Skeleton），不转整页 Spin |
| 同步中 | 顶部按钮 loading；来源状态显示“同步中” |
| 单源失败 | 顶部 `Alert` 非阻断提示，保留旧数据；提供重试 |
| 授权过期 | `Alert` + “重新连接”，不静默丢数据 |
| 无新内容 | `Empty` + 解释 + “模拟/立即同步” |
| 搜索无结果 | `Empty` + 清除搜索 |
| 保存反馈 | `message.success`，2–3 秒消失 |
| 危险操作 | `Popconfirm` 或 Modal 二次确认 |

反馈原则来自 Ant Design：必要、即时、不过度；能直接看到结果的操作不要弹一堆提示。

## 8. 组件映射

| Ant Design | Cove 用法 | 备注 |
|---|---|---|
| `Layout` / `Sider` | 应用壳、侧栏 | 固定侧栏，内容滚动 |
| `Menu` | 简报 / 数据源 / 设置 | 选中态用 primary tint |
| `Typography` | 标题、正文、元信息 | 14px 基准，两个字重 |
| `Card` | 单条信息、统计块 | 不网格化 feed |
| `Badge` | 注意力状态、同步状态 | 文字和颜色同时出现 |
| `Tag` | 内容类型、行动、反馈 | 4px 圆角，不用作 critical |
| `Segmented` | 来源筛选、时间窗口 | 替代一排 pill 按钮 |
| `Input` | 搜索 | 带前缀图标 |
| `Switch` | 只看需要行动 | 标签明确 |
| `Collapse` | 已折叠区 | 默认收起 |
| `Drawer` | 详情 | 640px，保留上下文 |
| `Modal` / `Form` | 分类反馈 | 不做全屏向导 |
| `Alert` | 同步失败、授权过期、演示提示 | 非阻断 |
| `Descriptions` | 判断字段 | 两列，窄屏一列 |
| `Statistic` | 简报统计 | 数字 tabular |
| `Empty` / `Result` | 空状态、错误结果 | 带下一步动作 |
| `Skeleton` | 首次加载 | 卡片形状骨架 |
| `Tooltip` | 字段解释 | 不承载长文 |
| `Popconfirm` | 清除本地数据 | 二次确认 |

## 9. 可访问性

- 正文对比度 ≥ 4.5:1；主色按钮白字对比度已满足；
- 不用颜色作为唯一状态，必须配文字或图标；
- 键盘可到达所有筛选、卡片操作、Drawer 关闭；
- 焦点环使用 primary，不用 `outline: none`；
- 触控目标至少 32×32；图标按钮带 `aria-label`；
- 动态结果用 `aria-live` 或 message；
- 支持 `prefers-reduced-motion`；
- 中文正文行高不低于 1.6。

## 10. 文案

- 说“判断”和“证据”，不说“AI 已确认”；
- 说“需要你处理”，不说“系统要求”；
- 说“未知/待确认”，不补全成事实；
- 同步失败说明“哪个来源、什么原因、可以做什么”；
- 不用“智能”“一键”“彻底解决”等空话。

示例：

```text
过去 24 小时有 14 条更新，其中 6 条需要你处理。
同步失败：Ed 会话已过期。旧数据仍然保留，请重新连接后重试。
没有新内容。下一次同步发生在你打开应用时。
```

## 11. 实施建议

第一版本地 Web App：

```text
webapp/
├── src/
│   ├── app/
│   ├── components/
│   ├── pages/
│   ├── features/brief/
│   ├── features/sources/
│   ├── features/detail/
│   ├── theme/
│   └── data/
├── index.html
└── vite.config.ts
```

技术：

- Vite + React 19 + TypeScript；
- `antd` v6（仓库当前 6.6.8）+ `@ant-design/icons`；
- `ConfigProvider` 统一主题，不写散落 CSS；
- 本地 Node 服务后置：先做 UI 与 mock 数据，再接 OAuth/同步；
- 主题 token 集中在一个文件，禁止页面级硬编码色值；
- 先做 Brief + Drawer + Empty/Error 三个状态，再扩展数据源页。

## 12. 验收清单

- [ ] 1440 画板下侧栏 232、内容最大 960，阅读行长合适；
- [ ] 主色、语义色、文本色全部来自 token；
- [ ] 页面只有一个 primary 按钮；
- [ ] critical 同时有文字和状态，不只靠颜色；
- [ ] 卡片不是 2×2 网格，feed 单列可扫读；
- [ ] 详情用 Drawer，不打断列表上下文；
- [ ] 加载、空、搜索无结果、同步失败、授权过期都有状态；
- [ ] 键盘可以完成筛选、打开详情、提交反馈；
- [ ] 所有小字 ≥ 12px，正文 14px；
- [ ] 没有直接复制 Ant Design 的蓝色后台外观。

## 13. 已采用与待确认

已采用：

- 主色 `#1F5A46`，白字对比度满足 AA；
- 首次进入显示最近 24 小时；
- 详情只保留一个 Drawer，宽度 640px，移动端全宽；
- `<768px` 使用 72px 图标栏，而不是顶部导航抽屉。

仍待确认：

- 是否需要在第一版支持暗色模式（建议 P1）；
- 移动端是否改为顶部导航抽屉；
- 详情 Drawer 是否允许在桌面并排打开。
