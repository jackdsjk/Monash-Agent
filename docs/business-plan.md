## 一句话

**把散落在 GitHub 上的 Monash 开源工具，打包成一个双击就能用的 Windows 软件，在小红书卖给不会配置命令行的中国留学生，¥15–29 一份。**

## 一、这个生意为什么存在

三个同时成立的事实，缺一个就不成立。

| 事实 | 证据 |
|---|---|
| **工具已经做好了，而且免费** | 8 个 Moodle 读取器、5 个 Ed 读取器、1 个记忆层，最好用的几个是 MIT |
| **但它们只有 CLI，非 CS 的人用不了** | 需要 Node 22、`npm i -g`、配 MCP、过 SSO —— 中文留学生里能独立完成的比例极低 |
| **没人做分发** | 最完整的两个成品 32★，`monash-study-kit` 一个月 0★。它们只在 CS 圈子里流动 |

**我们卖的不是代码，是"消除激活成本"。**

这也是为什么这件事能成立：原作者是 CLI 优先的（他们明确说目标是"给脚本和 agent 用"），**他们不会来做 Windows 安装器和中文引导**。那部分苦工没人愿意干。

## 二、产品定义 v1

### 是什么

一个 Windows 桌面应用，装完图标在桌面，打开就是：

```
┌─────────────────────────────────────┐
│  今天                               │
│  ─────────────────────────────      │
│  FIT2102  A2 作业   明天 23:59      │
│  FIT2109  Quiz 3    周五            │
│                                     │
│  最近公告                           │
│  · Week 7 lab room change   (Ed)    │
│  · 期中考试安排              (Moodle)│
│                                     │
│  成绩                               │
│  FIT2102  Assignment 1   17.5/20    │
└─────────────────────────────────────┘
```

### 做什么

- 自动发现 Moodle 站点（`moodle auth site`）
- 一次性 SSO 登录（MFA 由学生本人完成）
- 读：截止日期、公告、成绩、课程文件列表
- 本地缓存，离线可看
- 托盘常驻，每天早上弹一次"今天有什么"

### 不做什么（v1 明确砍掉）

| 砍掉 | 原因 |
|---|---|
| 云端账号 / 服务器 | 一旦托管学生数据，你就是数据处理者，PDPA 义务全套上来 |
| 上传任何数据 | 同上。**卖软件，不卖服务** |
| Ed / OnTrack | v1.1 再说，先把 Moodle 跑稳 |
| 自动提交作业 | 出一次事故就完了 |
| 移动端 | 不做 |
| AI 对话 | 不做。v1 是"看得清"，不是"会聊天" |

## 三、技术形态（关键决策已定）

### 必须自带 Node 运行时

查证结果：**`moodle-cli` 官方 release 只提供 `darwin-arm64` 和 `linux-x64`，没有 Windows 二进制。** 而 npm 包只有 6 个依赖。

所以：**用 Electron**。理由：

- Electron 自带 Node，用户不需要装任何东西
- 主进程可以以 Node 模式跑 CLI：
  ```js
  spawn(process.execPath, [cliPath], {
    env: { ...process.env, ELECTRON_RUN_AS_NODE: '1' }
  })
  ```
- 打包用 `electron-builder` 出 NSIS 安装器，双击即装

### 数据流

```
Electron 主进程
  ├─ spawn moodle <cmd> --json  → 解析 stdout
  ├─ 存 %LOCALAPPDATA%\MonashKit\cache.json
  └─ IPC → 渲染进程
```

**全程不发网络请求到我们的服务器。** 只有 Electron → Monash Moodle。

### 合规打包

- 必须随包附带 `moodle-cli` 的 `LICENSE`（MIT）和版权声明 `© bunizao`
- 应用内"关于"页写清楚：基于 `moodle-cli`（MIT）构建，独立项目，与 Monash 无隶属关系
- **不打包任何课件内容** —— 只下载到学生自己电脑

## 五、合规红线（不可越线）

### 只可用这些

| 组件 | 许可 | 可否商用 |
|---|---|---|
| `moodle-cli` | MIT | ✅ 可，保留 LICENSE |
| `edstem-cli` | MIT | ✅ 可 |
| `ontrack` | MIT | ✅ 可 |
| `okta-auth` | MIT | ✅ 可 |
| `unicorn` | Apache-2.0 | ✅ 可，保留 NOTICE |

### 绝对不能用

| 组件 | 许可 | 原因 |
|---|---|---|
| `Muster`（32★，最好看） | PolyForm **Noncommercial** | 禁止任何商业用途，收钱即违约 |
| `救驾 / jiujiastudy`（32★，最完整） | PolyForm **Noncommercial** | 同上 |
| `monmap`、`0xca1x/downloader` | AGPL | 可卖但必须提供源码，或做网络服务必须开源 |

> **这两条 Noncommercial 是硬墙。** 不管收 3 块还是 300 块、不管只卖安装包、不管谁运行 —— 收钱就违约。

### 三条不能碰

1. **不打包课件 / 录像 / 作业说明** —— 那是 Monash 和任课老师的版权
2. **不托管学生数据** —— 数据只在学生本机
3. **不代学生登录、不保存学生账号密码** —— SSO 由本人完成

### 一条建议

看一眼 Monash 的网站使用条款（learning.monash.edu 页脚），确认"自动化访问"的措辞。你不需要律师，只需要知道禁的是什么。

## 六、分发

### 主渠道：小红书

三条笔记，不同角度，测哪个转化最好：

1. **痛点型**：「Monash 的截止日期能不能别散了，我做了一个东西把它们放一起」+ 截图
2. **对比型**：「别人写的工具能用，但要装命令行 —— 我把它做成了双击就能用」
3. **时间线型**：「开学第一周我差点错过的三件事」

**关键指标**：收藏 > 点赞。收藏说明"以后要用"，是购买意图。

### 承接：私域

小红书对虚拟商品和站外导流管得严。设计成：

```
笔记 → 评论区/主页引导 → 微信 → 收款发下载链接
```

- 准备**备用号**（这是必需品，不是可选项）
- 个人转账没有交易保障 → 先发安装包再收钱，把争议降到零
- 退款规则写在显眼处：装不上全额退

### 已有竞争者

`Waldo0926/mumguide-wechat-bot`「马莫百科」已经在做中文留学生渠道，走"规则优先、只引用不编造"路线，**2026-10-25 还在更新**。渠道不是空地，要靠"安装包"这个形态差异切入。

## 七、时间表（4 周）

| 周 | 目标 | 完成标志 |
|---|---|---|
| **W1** 技术验证 | Electron 壳 + 拉起 `moodle-cli` + Windows 上走通 SSO | 在你自己的 Windows 机上，点一下登录成功，能看到真实截止日期 |
| **W2** 产品化 | 三个页面（今天/成绩/公告）+ NSIS 安装包 | 发给一个没装过 Node 的同学，他能自己装好并登录 |
| **W3** 内测 | 10 个同学试用 | 记录每一个"装不上"的具体原因，修掉 Top 5 |
| **W4** 上线 | 小红书 3 条笔记 + 收款流程 | 第一单成交 |

### W1 必须先验证的技术未知（按风险排序）

1. **SSO 弹窗在 Windows 上怎么走** —— `moodle auth login` 是"CLI 控制的浏览器"。它是否需要 Chrome？Edge 够不够？会不会和 Electron 窗口冲突？
2. **`ELECTRON_RUN_AS_NODE` 跑 CLI 是否正常**（ESM + `engines: node >=22.13`）
3. **中文路径 / 用户名带空格** 会不会让 CLI 崩
4. **校园网/VPN** 是否拦截

这四条只要有一条不过关，成本结构就变了（可能要改 Tauri 或者干脆卖"帮装"服务）。
